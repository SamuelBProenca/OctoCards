Use a API do seu jeito.

OctoCards coleta dados de repositórios públicos do GitHub e os entrega em JSON. O playground é uma demonstração; sua aplicação pode consumir a API diretamente, sem depender da interface incluída.

O dado é a interface.

Use o JSON em um site estático, React, Vue, outro framework ou qualquer cliente HTTP. O consumidor não precisa conhecer o token do GitHub configurado no servidor OctoCards.

Comece com uma chamada

Use o domínio da instância publicada ou o endereço local do backend. Se a sua página e a API estiverem no mesmo host, window.location.origin funciona para ambos.

Online

Substitua SEU_HOST pelo domínio publicado.

curl "https://SEU_HOST/api/cards/OctoCards?owner=SamuelBProenca"

Local

Usa a porta padrão 3000.

curl "http://localhost:3000/api/cards/OctoCards?owner=SamuelBProenca"

Buscar uma coleção em JavaScript

Exemplo para uma página servida no mesmo host da API.

const apiBaseUrl = window.location.origin;
const params = new URLSearchParams({
  repos: "OctoCards,LinkKeeper",
  owner: "SamuelBProenca"
});
const requestUrl = new URL("/api/cards", apiBaseUrl);
requestUrl.search = params.toString();

const response = await fetch(requestUrl);
const result = await response.json();

if (!response.ok) {
  throw new Error(result.error?.message ?? "Falha ao consultar OctoCards.");
}

console.log(result);

No PowerShell, use curl.exe se curl chamar o alias do próprio PowerShell.

Executar localmente, sem o playground

O backend atende as mesmas rotas da API. Com PLAYGROUND_ENABLED=false, ele não serve a vitrine de repositórios em /; a documentação, o OpenAPI e a API continuam disponíveis.

  1. Instale Node.js e npm.
  2. Entre em backend e instale as dependências.
  3. Copie .env.example para .env e ajuste as variáveis.
  4. Inicie o backend e faça chamadas ao endereço local pelo terminal ou pela sua aplicação.

Comandos

Execute na raiz do repositório.

cd backend
npm install
# Copie .env.example para .env e configure o ambiente.
npm run dev

Variáveis de ambiente

TOKEN é opcional e fica no backend.

OWNER=octocat
PORT=3000
TOKEN=
GITHUB_TIMEOUT_MS=10000
PLAYGROUND_ENABLED=false
API_RATE_LIMIT_MAX=12
API_RATE_LIMIT_WINDOW_MS=60000
TRUSTED_PROXIES=

Para habilitar o playground local, configure PLAYGROUND_ENABLED=true. Sem a variável, o padrão é true. Nunca coloque TOKEN no navegador ou no código do cliente. O limite padrão é 12 requisições por IP a cada 60 segundos; esse controle é em memória por processo.

Rotas da API

owner é opcional; quando omitido, o servidor usa OWNER (até 39 caracteres). Nomes de repositório aceitam letras ASCII, números, ponto, hífen e sublinhado, com até 100 caracteres. Uma coleção aceita até 10 itens e 2048 caracteres na query; nomes repetidos sem diferenciar maiúsculas/minúsculas são consultados uma vez.

Método e rotaParâmetrosResposta
GET /api/cards/:repoowner opcionalUm objeto de cartão
GET /api/cardsrepos obrigatório; owner opcionalUm array de cartões

Consultar vários repositórios

A ordem da resposta acompanha a ordem enviada.

curl "http://localhost:3000/api/cards?repos=OctoCards%2CLinkKeeper&owner=SamuelBProenca"

Se qualquer item falhar, a requisição da coleção retorna um erro em vez de resultados parciais.

Formato do cartão

Este exemplo mostra a estrutura, com valores ilustrativos. description contém o README bruto em Markdown; sua aplicação escolhe como renderizá-lo.

Objeto de resposta

Uma consulta de coleção retorna um array desses objetos.

{
  "name": "OctoCards",
  "description": "# OctoCards\n...",
  "principal_languages": ["TypeScript"],
  "stars": 0,
  "forks": 0,
  "url": "https://github.com/OWNER/REPO",
  "illustration_image_url": "https://..."
}
CampoConteúdo
nameNome do repositório.
descriptionREADME em Markdown; usa Sem descrição quando não existe README.
principal_languagesLinguagens detectadas pelo GitHub.
stars / forksContagens retornadas pelo GitHub.
urlEndereço do repositório no GitHub.
illustration_image_urlImagem escolhida para a capa ou um placeholder.

Erros e recuperação

Respostas de erro contêm error.code e error.message. Confira o status HTTP antes de usar o corpo como cartão.

HTTPCódigoAção
400INVALID_REQUESTConfira owner, repo e nomes da coleção.
401 / 403GITHUB_UNAUTHORIZED / GITHUB_FORBIDDENVerifique a credencial e as permissões no servidor.
404REPOSITORY_NOT_FOUNDConfirme owner e repo. Repositórios privados também retornam 404.
429API_RATE_LIMITED / GITHUB_RATE_LIMITEDAguarde o cabeçalho Retry-After; o limite pode ser da API OctoCards ou da cota do GitHub.
502 / 504UPSTREAM_ERROR / GITHUB_TIMEOUTTente novamente quando o GitHub estiver disponível.
500CONFIGURATION_ERROR / INTERNAL_ERRORRevise configuração e logs do servidor.

Limites e segurança

  • O provedor implementado é GitHub e apenas repositórios públicos são retornados.
  • O token do GitHub pertence ao backend. Clientes da API não enviam essa credencial.
  • Por padrão, cada IP pode fazer 12 chamadas de API por janela de 60 segundos. Ajuste API_RATE_LIMIT_MAX e API_RATE_LIMIT_WINDOW_MS no servidor. A cota fica em memória por processo.
  • Se houver proxy reverso, defina somente os IPs/CIDRs confiáveis em TRUSTED_PROXIES; sem isso o backend ignora cabeçalhos encaminhados para identificar clientes.
  • Há cache em memória de cinco minutos, limitado a 500 cartões por processo; reiniciar o servidor limpa o cache.
  • A cota do GitHub é compartilhada pela instância. Uma coleção sem cache pode usar várias consultas.
  • A API está em alpha e ainda não tem prefixo de versão; o contrato pode mudar antes de uma versão estável.
